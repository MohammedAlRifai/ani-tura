# عين المستشفى — نسخة العمليات المصححة

هذه نسخة محلية لمنشأة واحدة وخادم واحد. قاعدة البيانات مؤجلة حسب الطلب. تحفظ العمليات في ملفات JSON محلية عبر الخادم مع معاملات على نسخة منفصلة وكتابة ملف مؤقت ثم استبداله.

## التشغيل

1. ثبّت Node.js 22 أو أحدث، ثم افتح مجلد المشروع.
2. شغّل `npm install`.
3. شغّل `npm run dev` وافتح `http://localhost:3000`.
4. عند أول تشغيل ينشئ الخادم ملف `.local-runtime/access.txt` ببيانات الدخول المحلية لكل حساب. يحتوي `accounts.json` على مشتقات كلمات المرور المملحة. لا تشارك مجلد التشغيل ولا تضمه إلى مستودع أو حزمة تسليم.
5. اختيار حساب مختلف يتطلب كلمة مروره. يفرض الخادم الصلاحيات، وتبقى الجلسات لمدة ثماني ساعات كحد أقصى وتنتهي بإعادة تشغيله.

للفحص: `npm run lint` ثم `npm test`.
للبناء: `npm run build` ثم `npm start`. الإقلاع الثاني يستخدم ملفات البناء. يلزم HTTPS عند تشغيل وضع الإنتاج على خادم فعلي لأن ملفات الجلسة Secure.

## العمليات

- البلاغ: جديد ← إسناد وبدء العمل ← تقرير الإنجاز وصرف قطع الغيار ← بانتظار الاعتماد ← اعتماد مراجع مستقل وإغلاق. إعادة الفتح للإدارة مع سبب. يرفض الخادم النسخة القديمة من البلاغ عند التعارض.
- المعايرة: فحص ناجح ينتج مسودة ويظل الجهاز معزولًا حتى اعتماد مستخدم مستقل. الفشل يبقيه خارج الخدمة. يمنع اعتماد نتيجة قديمة أو إعادة جهاز أثناء استدعاء حرج مفتوح. الجهاز الجديد يحصل على فحص قبول قبل التشغيل.
- المخزون: حركة مؤكدة بالخادم، ومنع الصرف الزائد وتكرار الطلب. الأدوية والمحاليل والكواشف تتطلب دفعات وصلاحية عند الاستلام، ويصرف منها حسب الأقرب انتهاءً. الأرصدة التجريبية السابقة بلا دفعات لا تصبح مؤهلة للصرف تلقائيًا.
- الشراء: مسودة ← اعتماد داخلي من الإدارة ← قيد التوصيل بعد تأكيد المورد خارج النظام ← محضر استلام وفحص جزئي أو كامل. لا تنشأ فاتورة تلقائيًا. يُفصل طلب كل مورد، ويُحتسب المبلغ من الكتالوج الداخلي في الخادم.
- فاتورة الشراء: ترتبط بأمر مستلم كاملًا ومحضر فحص، وتطابق المورد والرصيد غير المفوتر، ثم تحفظ كمسودة للاعتماد الداخلي. لا ينفذ النظام تحويلات مالية.
- العمل دون اتصال: يمكن حفظ بلاغ في جلسة مفتوحة في طابور محلي يحمل هوية صاحبه. تبقى العمليات المرفوضة مع سببها. عمليات الرصيد والمعايرة والاعتماد تتطلب الاتصال. لا تدّعي النسخة إتاحة إعادة تحميل التطبيق بالكامل دون اتصال.
- العقود والخدمات المساندة وإعدادات المنشأة وإجراءات الاستدعاءات تحفظ عبر الخادم وتظهر في سجل التدقيق. يمكن ضبط أهداف الاستجابة بالدقائق للبلاغات الجديدة من إعدادات المنشأة؛ لا توجد أهداف اعتماد مفترضة.
- حُذف شريط النسخة التشغيلية وقسم نظام التصميم من واجهة العرض.

## البيانات والتكامل

البيانات الابتدائية أمثلة عرض. الموردون والاستدعاءات ليست تغذية حية من جهات خارجية. كتالوج المورد لا يعرض رصيد المستشفى على أنه توفر المورد. تكامل HIS/ERP/SSO الحقيقي وإعداد حسابات الموردين مرحلة لاحقة. منار يستخدم مزودًا خارجيًا عند إعداد GEMINI_API_KEY؛ وإلا يعمل الرد المحلي الموضح في التطبيق.

الإشعارات لها مفاتيح VAPID واشتراكات محفوظة محليًا وتوجيه للأدوار المستهدفة وصاحب البلاغ، مع تفضيلات المستخدم. يفصل الاشتراك عن الحساب عند الخروج. لم يُختبر في هذه المهمة وصول رسالة فعلية عبر مزود إشعارات خارجي إلى جهاز مسجل.

## التحقق المنجز

- نجح فحص TypeScript بعد إضافة تعريفات React اللازمة.
- نجحت 21 حالة اختبار تشمل المعايرة، العزل والاستدعاء الحرج، منع تكرار المزامنة، التراجع عن المعاملة عند الفشل، الصلاحيات، الإسناد، الدفعات، الاستلام الجزئي ومطابقة الفاتورة.
- نجح بناء الواجهات والخادم بصيغة ESM. فُحص إقلاع نسخة البناء على منفذ منفصل: health وواجهة HTML أعادا 200 دون عميل Vite.
- أعادت مسارات ملفات التشغيل الخاصة 404، وواجهة البيانات دون جلسة 401.
- فُحص تسجيل الدخول والتنقل ونموذج البلاغ المرتبط بالجهاز والتعبئة التلقائية للموقع وEsc وعودة التركيز في المعاينة.

لم تتضمن المهمة اختبار تحمل مؤسسيًا، أو اختبار اختراق شاملًا، أو تكاملًا حيًا مع منظومة مستشفى، أو اعتمادًا تنظيميًا. الملفات المحلية ليست بديلًا للبنية المركزية والنسخ الاحتياطي والإدارة المؤسسية عند النشر الفعلي. يوجد تحذير بناء غير مانع بشأن حجم حزمة PDF؛ تحميل الأقسام والنوافذ أصبح عند الطلب.
